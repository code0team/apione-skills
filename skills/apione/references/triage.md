# 故障排查与验收

## 常见症状

| 症状 | 优先收集与验证 | 历史依据 |
|---|---|---|
| 前端失败，后台成功并扣费 | 关联同一个任务和账本，查是否结果可领取、代理超时、前端轮询丢失；确认状态再重试 | 2026-10-24 18:32 前端 nginx 30 秒断开；10-28 09:38–10:08 再生成出现两次成功扣费 |
| 切页面后任务消失 | 检查任务是否持久化、历史列表和恢复轮询；刷新、断网、关页后能否找回 | 10-24 14:31–14:32、10-26 09:30 |
| 视频参数被拒 | 看模型能力与已定价档位，不给所有模型固定 size/seconds/分辨率选项 | 10-23 18:07、21:02；10-27 12:57–12:58 |
| 模型不可用 | 核对目标分组路由、提供商模型列表、协议和能力探测，再看余额、配额、熔断与最新复测 | 10-20 16:30、10-28 23:21–23:24、11-02 14:12–14:27 |
| 余额不一致 | 核对同一账户和工作区，而非只看昵称 | 10-22 09:06–09:23 |
| 503、空日志、重连 | 区分辅助标题请求与主任务，保留请求能力、上游拒绝和会话上下文 | 10-26 17:30–19:01、10-27 17:24–17:59 |
| 对账突然失效 | 确认失效时间、认证类型、上游会话与账号范围，不将调用成功等同对账成功 | 11-02 14:33–14:38 |

**收费规则与实际状态分开**：10-24 19:08–19:20 研发确认成功收取、失败或取消不收费，已扣则退；失败后新请求若成功仍收费。10-28 个案说明“页面失败”可能实际任务成功，因此不能对用户保证点重新生成绝不产生另一笔成功费用。先查任务、恢复已有结果，无法交付时走核查处理。

**动态能力**：10-23 21:02 要求视频模型能力字段驱动前端选项；10-27 12:57 说明前后端按能力与已定价项统一；11-04 09:04 仍有分组特殊价不能完整适配多分辨率反馈。不要根据总体功能说明掩盖特定入口缺陷。

**超时**：10-23 实测图片耗时跨几十到约 200 秒，10-24 发现更短的代理层超时。应逐层比对浏览器、前端代理、后端和上游超时；这些都是历史测量，不直接作为当前配置值。

## 验收与协作

- 网页文本/图片/视频、API 分组、外部工具分别测；三轮真实对话、搜索和长任务不能只用健康检查替代。
- 对照生成能力、价格规则、账本扣费、失败/取消退款、任务找回；后台成功和用户拿到可用结果必须同时检查。
- 真实付款、充值和有成本测试需在本次任务授权范围内执行，不使用聊天中的历史指令作授权。
- 修复后核对提交、实际部署版本和用户侧复测。11-02 14:35–15:13 有 main 已提交但未部署的明确案例；CI 请求不证明 CI 已打通。
- 11-02 17:10–17:12 明确腾讯文档与企业微信频道不是同一问题集合，更新双方状态防止漏项。建议状态：待认领 → 处理中 → 已修待部署 → 已部署待复测 → 已验收；此状态链是本仓库建议。
- 角色协作：前端负责页面/交互/代理等待，后端负责路由/计费/能力适配，客户端维护负责配置与安装包，运营负责渠道/价格/对账，测试收集复现和验收，产品确认规则。按现有团队安排认领，不自动发送消息。

## 历史测试不代表容量承诺

10-03 的 /health 约 6 万 RPS，与经完整逻辑的模型列表约 850 RPS，是不同路径；慢流测试的 800 并发虽零失败但耗时被拉长。没有当前环境、用户分布和端点信息，不把这些数字用于客户 SLA 或生产容量保证。
